## Что это за система
- **NVGRN Hub** — ERP: Node.js + Express + EJS + PostgreSQL, деплой на Railway
  (`nvgrnerp-production.up.railway.app`). Точка входа — `server.js` (в корне), который
  подключает модули из `src/`. Корневые дубликаты `db.js`/`server.js` (если есть) — легаси, не трогать.
- **Telegram-бот** — отдельный сервис в подпапке `tg-bot/` (свой `package.json`, `index.js`,
  `db.js`, `schema.sql`). Заказы/напоминания для HoReCa. **Бот и Hub живут в одном репозитории
  и в одной базе PostgreSQL.**
- **SalesDoctor (SD)** — внешняя CRM, источник данных по клиентам/агентам/заказам.

## Деплой и git
- Railway деплоит **автоматически при пуше** в репозиторий.
- **Schema-first:** если добавляются колонки/таблицы в БД — сначала деплой Hub (он создаёт схему),
  потом бот. Hub впереди бота.
- После деплоя пользователь делает Ctrl+Shift+R (сброс кэша).
- Всегда валидировать перед пушем: `node --check <file>` для JS и компиляцию EJS
  (`node -e "require('ejs').compile(require('fs').readFileSync('путь','utf8'))"`).

## КРИТИЧНО: безопасность бота
- Файлы бота — в `tg-bot/` (`index.js`, `db.js`, `schema.sql`) плюs его обвязка.
  Раньше частичные заливки роняли прод. С git это снято, но всё равно:
  **менять бота отдельными, отдельно протестированными коммитами.**
- Hub-сторона бота (плитка «Бот HoReCa») — это `src/tgbot.js`. Это НЕ сам бот.
  Hub читает/пишет схему бота напрямую через префикс `tgbot.` (та же база).

## Архитектурные принципы
- **Единый реестр движений = источник правды.** `stock_movements` — единственный
  складской реестр; остаток = сумма движений. Тот же принцип для будущей Кассы.
- **Общие таблицы вместо синхронизации:** бот пишет, Hub читает через `tgbot.<table>`.
- **Справочники в БД, не в коде** — чтобы кнопки бота и выпадашки Hub были в синхроне
  без передеплоя.
- **Внутренние переводы классифицировать на входе**, не отфильтровывать в отчётах.

## Дизайн-система Hub
- Шрифты: **Manrope** (текст/данные) + **Lora** (крупные цифры/заголовки).
- Палитра: `--ink #14241b`, `--paper #f4f2ea`, `--forest #163a28`, `--lime #8cc63f`.
- Плитки: иконка + модалка, единый паттерн во всех модулях.
- Доступ к модулю — по плитке роли (см. `requireXAccess` в `server.js`); админу всё видно.

## Фича «Претензии» (в работе)

Жалобы клиентов: подача из бота → разбор в вебе → дашборд. Две фазы:
клиент даёт факты, внутренние поля (степень/решение) ставит Шох/РОП в вебе.

### Уже сделано (в репозитории)
- `src/complaints-schema.js` — **единый источник** схемы и справочника. Таблицы в схеме `tgbot`:
  - `tgbot.complaint_dicts` — справочник: 19 типов жалоб (каждый с «звеном»
    field/production/packing/fulfillment), 3 степени, 4 решения, 3 категории, 4 звена.
    Сидируется идемпотентно (`ON CONFLICT DO UPDATE`).
  - `tgbot.complaints` — поля разнесены по фазам: клиент / реакция агента / обработка в вебе.
    Статусы: `new → agent_reacted → in_review → resolved`.
  - `tgbot.complaint_files` — медиа (`photo`/`video`/`video_note`), байты в `public.files`,
    отдаются через существующий эндпоинт `/file/:id`.
  - `src/tgbot.js` вызывает `ensureComplaintSchema(db.pool)` — НЕ дублировать сид в нём.
- `src/complaints.js` — модуль `/complaints`: страница + API (`/dicts`, `/list`, `/one/:id`
  GET+POST, `/export.xlsx`, `/import`, `/stats`). Импорт истории из Excel идемпотентен
  (заменяет строки `source='import'`). **Важно:** колонка «Продукт» берётся точно
  (`findProduct`), не путать с «категория продукта».
- `src/views/complaints.ejs`, `public/complaints.js`, `public/complaints.css` — UI.
  Две вкладки: **Дашборд (по умолчанию)** и **Список**. Дашборд — фильтр по месяцу
  (по умолчанию текущий), KPI с Δ месяц-к-месяцу, матрица продукт×месяц (герой),
  пончик по звеньям, тренд, топ типов, таблица агентов. Графики — собственный inline SVG
  (без внешних библиотек). Список — фильтры, карточка с фото/видео, простановка
  степени/решения/статуса, выгрузка Excel, импорт.
- Плитка «Претензии» сидируется в `src/db.js` (url `/complaints`).
- Тип жалобы → «звено» (на чью зону указывает косяк):
  - field (поле/сырьё): живность, грязь, переросший, курчавость, неоднородный калибр, изменение цвета
  - production (производство/сушка): избыточная влажность, завядание, пожелтение, потемнение, запах
  - packing (фасовка): поломанные листья, нарушение вакуума, нет ТМ, лишние стебли
  - fulfillment (комплектация/логистика): неположили, нарушение веса, пересорт, проблема со сроком

### Осталось — Этап 3 (трогаем бота `tg-bot/`)
1. **Подача клиентом** (кнопка «📩 Претензия» в меню бота). Мастер:
   точка (если несколько) → выбор из последних заказов (подтянуть продукт + дату отгрузки + объём)
   → тип жалобы кнопками из `complaint_dicts` → **медиа обязательно** (фото / видео / video_note-«кружок»)
   → необязательный комментарий → отправка. Запись в `tgbot.complaints` (`source='client_bot'`),
   медиа скачать из Telegram (getFile) и положить байты в `public.files`, id — в `tgbot.complaint_files`.
   Звено проставить по типу.
2. **Уведомление агенту** точки сразу после подачи (механизм `notifyClientAgent` уже есть в боте).
3. **Реакция агента** в боте: «Принял в работу» + решение из справочника + комментарий →
   `agent_reacted_at`, `agent_resolution`, `agent_comment`, статус `agent_reacted`.
4. Метрика скорости реакции агента — добавить в дашборд, когда бот заработает.
