# План: один список людей — пользователи ERP

Решение Шоха (сентябрь 2026). Статус шагов — отмечать здесь по мере работы,
чтобы продолжить мог любой разговор или агент коллеги.

## Зачем
Люди жили в двух списках: **пользователи ERP** (Админ-панель → Пользователи, роли
= доступ к плиткам) и **Telegram-сотрудники бота** (плитка «Бот HoReCa», роли
агент / водитель / РОП / логистика). Заводить приходилось дважды, статусы
расходились («подтверждён» в боте и «ждём в боте» в ERP).

## Главный принцип — ничего не должно сбиться
- Заводим и меняем людей **только в пользователях ERP**.
- **Бот не переписываем.** Его таблица `tgbot.telegram_staff` заполняется из ERP
  автоматически (односторонняя сверка, как `src/driver-sync.js`).
- Связь с Telegram (`telegram_user_id`, `telegram_chat_id`) **не трогаем** —
  переподключаться никому не нужно.
- Из `telegram_staff` ничего не удаляем. Откат = выключить автозаполнение.

## Решения Шоха
- У каждого человека независимо: **доступ в веб** (да/нет) и **роль в боте**.
  Агентам и водителям веб не нужен. Руководителям — опционально и то, и другое.
- **Агенты и водители заводятся автоматически из SalesDoctor**: активный в SD —
  появляется (без веба), неактивный/удалён — отключается.
- Одна роль в боте на человека (у бота так устроено). Роли ERP (плитки) — отдельно.

## Поля пользователя ERP (`users`)
| Колонка | Смысл |
|---|---|
| `web_access` BOOLEAN default true | можно ли входить в веб-версию |
| `bot_role` TEXT | agent / expeditor / head_of_sales / logistics / marketing / admin / NULL |
| `sd_agent_id` TEXT | для агента — id агента в SD |
| `sd_expeditor_id` TEXT | для водителя — id водителя в SD |
| `source` TEXT | кто завёл: manual / sd_agent / sd_expeditor |
| `tg_phone`, `tg_chat_id` | уже есть |

`tgbot.telegram_staff.hub_user_id` — ссылка на пользователя ERP.
