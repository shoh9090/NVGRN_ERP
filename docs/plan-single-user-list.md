# План: кто где заводится — бот и ERP

Решение Шоха (сентябрь 2026), упрощённый вариант. Статус шагов отмечать здесь.

## Правило
- **Плитка бота → «Telegram-сотрудники» — только агенты и водители.** У них нет ERP,
  только бот. Водители заводятся сами из SalesDoctor (`src/driver-sync.js`).
- **Руководители (РОП, логистика, маркетинг, админ) — пользователи ERP**
  (Админ-панель → Пользователи): логин и пароль для веба, «Телефон (Telegram)» и
  **«Роль в боте»** — по ним бот узнаёт руководителя и шлёт сводки его роли.
- Галочки «доступ в веб» нет: логин и пароль — это и есть веб. (Колонка
  `users.web_access` в базе осталась со значением «да» и не показывается.)

## Шаги
- [x] **1. Интерфейс**: в модалке «Telegram-сотрудники» нет «Прочие», добавить можно
      только агента или водителя; в карточке пользователя ERP — «Роль в боте»
      (только роли руководителей).
- [x] **2. Бот берёт руководителей из ERP**: пользователь с «Ролью в боте» и
      подключённым телефоном получает меню своей роли и её рассылки (РОП —
      эскалации претензий, логистика — сводки доставки, подписки на оповещения).
      Старые строки руководителей в плитке бота продолжают работать, дубли
      сообщений исключены (по чату).
- [ ] **3. Перенос двух руководителей** (Абидов — логистика, О'гилой — РОП): в их
      карточке ERP указать телефон и роль в боте; убедиться, что сводки приходят;
      затем удалить их строки из плитки бота. Переподключаться им не нужно —
      чат связывается по телефону (`src/staff-link.js`).

## Попутно сделано и остаётся
- `src/web-access.js`: отключённый сотрудник теряет доступ сразу, а не когда
  истечёт сессия.
- Роли ERP (плитки) и «Роль в боте» — разные вещи: у бота одна роль на человека.
