# Как Claude смотрит данные ERP (без пароля от базы)

Короткая инструкция для разработчика и для его Claude. Проверено 23.09.2026.

## Главное правило: `DATABASE_URL` никому не пересылаем

Строка `postgresql://…` — это адрес, логин и пароль от боевой базы в одной строке.
Кто её получил, тот может читать и **менять что угодно**: зарплаты, деньги, заказы,
и удалить это одним неверным запросом. Восстановления «сразу» у нас нет.
Поэтому её не отправляют ни в чат, ни в файл, ни в переписку — она живёт только
в переменных Railway.

Отдельно: 22.09.2026 одна тяжёлая операция уже уронила базу на 17 минут. Это
делалось из кода, с проверками и откатом. Через «подключусь напрямую и посмотрю»
такое чинится куда дольше.

## Как надо: встроенный браузер Claude под своей учёткой ERP

Claude работает с ERP так же, как человек: открывает сайт, а данные читает через
те же адреса, что и экраны. Права — как у учётной записи, под которой вошли.

1. **Своя учётка в ERP.** Не общая. Заводится один раз:
   Персонал → карточка сотрудника → «Доступ в ERP» → логин, пароль, роль.
   Для разработчика обычно хватает роли с нужными плитками; полный админ — только
   если правда нужен.
2. **Открыть ERP во встроенном браузере.** Попросить своего Claude:
   > открой https://nvgrnerp-production.up.railway.app во встроенном браузере
3. **Войти самому.** Логин и пароль вводит человек. Claude пароли не вводит —
   это запрещено, и так и должно быть.
4. **Дальше Claude читает данные сам** — выполняет в открытой вкладке запросы к API.
   Вход живёт 12 часов, потом повторить шаг 3.

## Что можно прочитать (примеры)

```js
// P&L за месяц целиком
await fetch('/cash/api/pnl?period=2026-08').then(r => r.json())

// Готовность данных по месяцам (светофор)
await fetch('/cash/api/pnl/readiness?months=6&period=2026-09').then(r => r.json())

// Сверка Кассы с CRM по дням
await fetch('/cash/api/sd-reconcile?from=2026-09-01&to=2026-09-22').then(r => r.json())

// Транзакции Кассы (постранично: page, pageSize, from, to, type)
await fetch('/cash/api/transactions?from=2026-09-01&to=2026-09-30&type=in&page=1&pageSize=200').then(r => r.json())

// Претензии: список и карточка
await fetch('/complaints/api/list?limit=500').then(r => r.json())
await fetch('/complaints/api/one/682').then(r => r.json())

// Калькуляция: лист целиком с расчётом
await fetch('/calculation/api/sheet/vinegar').then(r => r.json())

// Склад: остатки на дату
await fetch('/stock/api/inventory?date=2026-09-22').then(r => r.json())

// Закуп: заявки за период
await fetch('/purchase/api/orders?status=all&from=2026-09-01&to=2026-09-30').then(r => r.json())

// Кадры: сотрудники
await fetch('/hr/api/employees?status=all').then(r => r.json())

// Только администратору: размер базы по таблицам, товар SD и его цены
await fetch('/admin/api/db-size').then(r => r.json())
await fetch('/admin/api/sd-good?sd=d0_161&remote=1').then(r => r.json())
```

Ответы — обычный JSON, те же данные, что на экранах. Права проверяются на сервере:
чего не видно роли, того не отдадут и здесь.

## Чего не делать

- **Не нажимать кнопки, которые меняют деньги, остатки и зарплату, без спроса.**
  Читать — свободно; писать — только когда человек сказал, что именно менять.
- **Не звать чужие сервисы от имени ERP** (SalesDoctor, Telegram) ради «посмотреть»:
  для этого есть готовые адреса ERP, и они не ломают лимиты.
- **Не держать вход открытым на чужом компьютере**: сессия живёт 12 часов.

## Если всё-таки нужен SQL

Бывает: сложная выборка, которой нет в API. Тогда правильный путь — **добавить
маршрут «только чтение»** в код (как `/admin/api/db-size`), выложить и позвать по
нему. Это занимает минуты, остаётся в истории изменений, и никому не приходится
пересылать пароль от базы.
