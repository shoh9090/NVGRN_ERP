# Джарвис: внутренний бот, Trello, штрафы — план и статус

Решения Шоха, сентябрь 2026. Этот файл — точка входа для продолжения работы.

## Зачем
Карточки в Trello висят: людей упоминают (@) — не отвечают, сроки карточек
проходят — никто не закрывает. Шох сам дёргает людей в Telegram. Нужно, чтобы
система напоминала сама, а за игнор — начисляла штраф в Персонал.
Дальше этот же бот становится «Джарвисом» — ИИ-помощником по должности.

## Главный принцип: каждая вещь — в одном месте
| Что | Где |
|---|---|
| **Человек** (ФИО, отдел, должность, телефон, Trello, доступ в ERP) | **Персонал → карточка сотрудника** |
| **Деньги человека** (оклад, штрафы, KPI, доля прибыли) | **Персонал** |
| **Правила** (доски Trello, сроки, суммы штрафов, что умеет Джарвис) | **новая плитка «Джарвис»** |
| **Права** (что видит роль) | Админ-панель → Роли (как есть) |

Джарвис отвечает человеку **строго в пределах прав его роли в ERP** (РОП не видит
закупочные цены в ERP → не увидит и в боте). Никаких отдельных списков прав.

## Готовые агенты с GitHub (разобрали 22.09.2026) — не ставим, берём идеи
Чужой агент = второй источник прав и второй сервис на другом языке (почти все
на Python). Строим сами на Node внутри Hub, модель — Claude API с инструментами.

- **NousResearch/hermes-agent** — Telegram-шлюз, cron, память о пользователе.
  Идея «помнить человека» — полезна на шаге 6. Сам не ставим: свои права,
  сам себе пишет навыки — недопустимо рядом с деньгами.
- **langchain** — для нашего объёма лишний слой; хватит Anthropic SDK с tools.
- **open-jarvis/OpenJarvis, isair/jarvis, RustamovAkrom/JARVIS** — локальные
  голосовые ассистенты для своего компьютера, к команде и ERP не подходят.
- **agent-reach** — чтение соцсетей/сайтов, для внутреннего бота не нужно.
- **affaan-m/ECC** — набор правил для Claude Code (разработчикам), не для бота.
  Не ставим: у нас свои правила (CLAUDE.md + `npm run verify`), чужие будут спорить.

## Претензии переезжают в Джарвиса (решение Шоха, 23.09.2026)

Сейчас ВСЯ механика претензий живёт в клиентском боте (`tg-bot/`), включая
внутреннюю часть: карточка руководителю звена, кнопки решения, «написать
причину», напоминания (`tg-bot/link-owners.js`, `reminderTick` в
`tg-bot/complaints.js`). Руководителю из-за этого стоит клиентский бот, и его
меню приходится прятать (`hubHelpIfStaff`, `applyHubMenu`).

**Делим по собеседнику:**
- **Клиентский бот остаётся** для клиентов и агентов: подача претензии с медиа,
  «Принял в работу», выбор решения агентом.
- **В Джарвис уходит внутреннее:** карточка руководителю звена, его решение,
  «написать причину», напоминания (сроки — в правилах Джарвиса рядом с Trello),
  сводки по претензиям в утренний список дел.

**Когда:** после шага 3 (бот запущен, вход по номеру работает). Не раньше —
сейчас претензии работают, ломать нечего.

**Что учесть при переносе:**
- руководителю надо один раз нажать «Поделиться номером» уже в Джарвисе:
  Telegram не даёт боту писать первым, пока человек не начал с ним диалог;
- права и «кто отвечает за звено» берутся там же, где сейчас:
  `tgbot.complaint_dicts.owner_role_id` → роль ERP → пользователи с телефоном;
- решение руководителя и причина ложатся в карточку претензии как сейчас
  (`resolution`, `resolved_by`, `internal_note`) — плитка уже показывает это
  колонкой «Закрыл», срезом «Ждут руководителя» и блоком в карточке;
- после переноса выключить в клиентском боте рассылку руководителям и
  напоминания, оставив подачу и реакцию агента.
