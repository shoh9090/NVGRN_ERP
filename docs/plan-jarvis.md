# Джарвис: внутренний бот, Trello, штрафы — план и статус

Решения Шоха, сентябрь 2026. Этот файл — точка входа для продолжения работы.

## Зачем
Карточки в Trello висят: людей упоминают (@) — не отвечают, сроки карточек
проходят — никто не закрывает. Шох сам дёргает людей в Telegram. Нужно, чтобы
система напоминала сама, а за игнор — начисляла штраф в Персонал.
Дальше этот же бот становится «Джарвисом» — ИИ-помощником по должности.

## Главный принцип: каждая вещь — в одном месте
| Что | Где |
|---|---|
| **Человек** (ФИО, отдел, должность, телефон, Trello, доступ в ERP) | **Персонал → карточка сотрудника** |
| **Деньги человека** (оклад, штрафы, KPI, доля прибыли) | **Персонал** |
| **Правила** (доски Trello, сроки, суммы штрафов, что умеет Джарвис) | **новая плитка «Джарвис»** |
| **Права** (что видит роль) | Админ-панель → Роли (как есть) |

Джарвис отвечает человеку **строго в пределах прав его роли в ERP** (РОП не видит
закупочные цены в ERP → не увидит и в боте). Никаких отдельных списков прав.

## Шаги
1. ✅ **Персонал ↔ пользователь ERP** (сделано 22.09.2026, `src/person-link.js`):
   - связь `hr_employees.erp_user_id`; автосвязка по телефону при запуске Кадров;
   - в карточке сотрудника блок «Доступ в ERP»: админ выдаёт доступ (логин/пароль/роль)
     или привязывает существующую учётку;
   - телефон ведётся в карточке сотрудника и сам уходит в `users.tg_phone`;
   - в Админ-панели у сотрудников «👤 ФИО · ведётся в Персонале», телефон там не правится;
   - связаны все 9 человек с учётками.
   - **Открыто:** у Абдушукура (purchase00) номера разные — в Персонале 97 740 74 74,
     в учётке 99 010 70 74 (бот знает по второму) — ждём от Шоха, какой верный.
     Лола Хидаева (активна в Trello) в Персонале — «уволена».
2. **Плитка «Джарвис»** — правила: контролируем ВСЁ рабочее пространство Trello;
   сроки; суммы штрафов. Сопоставление людей с Trello: система предлагает пары по
   имени, человек подтверждает (поле Trello — в карточке сотрудника Персонала).
3. **Чтение Trello + внутренний бот** (отдельный от клиентского, часть Hub, webhook):
   - вход по «Поделиться номером» → находим пользователя/сотрудника;
   - правила (часы рабочие 9:00–20:00, без ночи и выходных):
     - упомянули @ и нет ответа в карточке: напоминание через 4 ч, нарушение через 10 ч;
     - срок карточки прошёл, не выполнена: напоминание каждое утро 9:00, нарушение через 1 рабочий день;
     - карточка без движения 7 дней: одно напоминание, без штрафа;
   - кнопка «Ответить» — ответ из Telegram публикуется комментарием в карточке.
4. **Нарушения в Персонале**: черновик → руководитель отдела (Персонал → Отделы,
   `hr_user_departments`) в боте «✅ Провести / ❌ Отменить»; нет ответа за сутки —
   проводится сам; проведённое ложится в `hr_payroll.ded_fine` месяца (как выплаты:
   одна запись, отмена снимает). Штрафы включать ПОСЛЕ недели работы напоминаний.
5. Утренняя сводка, KPI, доля прибыли для топ-менеджмента.
6. ИИ-агент (Claude) поверх тех же инструментов бота: «мои дела», «продажи из SD»,
   «остатки», «прогноз закупа», «мои штрафы/KPI». Каждый инструмент со своим правом,
   каждый вопрос/ответ в журнал.

## Что нужно от Шоха для шагов 2–3
Токены — **только в Railway → Variables, Claude их не присылать**:
- `INTERNAL_BOT_TOKEN` — новый бот из @BotFather (например «Novagreen Команда»);
- `TRELLO_KEY`, `TRELLO_TOKEN` — trello.com/power-ups/admin.
Нерешённое: суммы штрафов (одна или разная за «не ответил» / «просрочил»).

## Готовые агенты с GitHub (разобрали 22.09.2026) — не ставим, берём идеи
Чужой агент = второй источник прав и второй сервис на другом языке (почти все
на Python). Строим сами на Node внутри Hub, модель — Claude API с инструментами.
- **aerele/jarvis** (ИИ внутри ERPNext) — образец замысла: каждый вопрос и действие
  выполняется с правами самого пользователя; изменения — черновиком на одобрение;
  журнал. Ровно наш шаг 6. Код не берём (Python/Frappe, AGPL).
- **NousResearch/hermes-agent** — Telegram-шлюз, cron, память о пользователе.
  Идея «помнить человека» — полезна на шаге 6. Сам не ставим: свои права,
  сам себе пишет навыки — недопустимо рядом с деньгами.
- **langchain** — для нашего объёма лишний слой; хватит Anthropic SDK с tools.
- **open-jarvis/OpenJarvis, isair/jarvis, RustamovAkrom/JARVIS** — локальные
  голосовые ассистенты для своего компьютера, к команде и ERP не подходят.
- **agent-reach** — чтение соцсетей/сайтов, для внутреннего бота не нужно.
- **affaan-m/ECC** — набор правил для Claude Code (разработчикам), не для бота.
  Не ставим: у нас свои правила (CLAUDE.md + `npm run verify`), чужие будут спорить.
